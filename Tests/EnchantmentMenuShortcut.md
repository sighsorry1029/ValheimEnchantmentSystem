# Enchantment menu shortcut and fixed options

## In-game checklist

1. Start with a fresh client config: `2 - Client` contains `UI - Keyboard Shortcut = Y`, `UI - Gamepad Shortcut = JoyButtonY`, and `UI - Gamepad Shortcut Modifier = JoyLBumper`, all marked not synced and stored under `[Client]`. A dedicated server should not bind these client UI entries. Put the old `UI - GamepadShortcut = JoyButtonX` entry in the cfg without the new entries: it must be ignored, not migrated, and the new default must remain LB + Y.
2. With both inventory and panel closed, press keyboard Y: both open on one press. Press Y again: only the enchantment panel closes and the inventory remains open. Press Y again: the panel reopens. Close the inventory and repeat. Open the inventory manually without opening the panel, then press Y: only the panel opens. Repeat after reconnecting/recreating InventoryGui. The mouse button must still toggle the panel normally.
3. Repeat keyboard toggling while the player-inventory, container, and crafting gamepad groups are selected: it must not require focus on the copied repair button's group. Hold an unrelated key while pressing Y: it still activates. Hold Y: no repeated toggling. Rebind to another key or `Y + LeftControl`: only the new binding works. Changing a binding while a key is held must not cause activation; release the buttons and retry. Set `None`: keyboard activation and its second hint line disappear, but mouse/gamepad remain available.
4. Repeat the closed-inventory and open-inventory flows with LB held before pressing controller Y, in each of the game's three controller layouts. Y without LB must retain its normal assigned game action. With a non-default binding, use that configured button and modifier instead. Gamepad activation must work from each inventory gamepad group without requiring repair/crafting focus.
5. Test pressing LB and Y simultaneously, holding both, releasing Y first, releasing LB first, and holding LB while releasing and pressing Y several times. Each fresh Y press with the modifier held must toggle exactly once; holding the buttons must not repeat. The activation must not also toggle the native inventory, switch an inventory tab, or trigger an overlapping native button action. An action caused by LB alone before Y was pressed is not a failure: standalone LB retains its normal behavior.
6. Change gamepad button/modifier settings while their buttons are held: no immediate toggle is allowed; release and retry. Set the main gamepad shortcut to `Disabled`: no gamepad activation or gamepad second hint line. Set only the modifier to `Disabled`: the main button works alone, with its potential normal-game binding conflict documented. Restore the defaults and verify LB + Y again.
7. Try both shortcuts while typing into chat, console, sign text, a TMP/InputField search box, Configuration Manager (including bind-key capture), or game settings. Also test menus, the large map, the store, split/variant/skills/texts/trophies inventory dialogs, the enchantment info panel, death, and a cutscene. They must not open or toggle the panel. Close the blocker while still holding the shortcut: the blocked press must not execute later. Release and press again in an allowed state: it works.
8. Hover the enchantment button: title is on the left and the smaller muted second line displays “Press Y to open the panel” (or close). Only the key/button names are orange, including keyboard modifiers and both buttons in the gamepad combination. The English second line omits “enchant”; Korean omits “강화”. Moving the cursor within the button must not move the label. Leaving it hides the label. The label must not intercept clicks, replace repair/item tooltips, or remain after inventory closes.
9. Check English and Korean; change the key or gamepad combination while the hint is shown. Switch between keyboard/mouse and gamepad focus: show the appropriate configured input label. Disabled gamepad binding must not show a misleading keyboard action while in gamepad mode. Check common resolutions, UI scales, and the existing modified inventory layout. The label should remain beside the button, within the canvas, without clipping either line under normal available space. At a very narrow viewport it may wrap/truncate instead of covering the button.
10. If deliberately binding Space/Return, one toggle press must not also execute an enchantment through the panel controller. Prefer non-conflicting keys: unrelated inventory/game/other-mod bindings are not globally suppressed. Confirm the temporary `VES Shortcut` / `[ShortcutDiag]` logging is no longer emitted.
11. Confirm neither Drop Enchantment On Upgrade nor Allow Jewelcrafting Mirror Copy Enchant appears in Configuration Manager or fresh cfg. Put their former entries back with `true`: they must be ignored. Upgrade an enchanted item's quality: enchantment remains. Mirror an enchanted item through Jewelcrafting: original retains enchantment, copy has none, and mirroring succeeds.

12. Enable the game's radial menu and release-to-use behavior. Hold LB, select a radial item without activating it, then press Y: the radial must cancel without using/equipping that item and both inventory/enchantment panels must open. Release LB and Y in either order: no delayed radial action or extra toggle. Test fast taps and different frame rates so fixed/dynamic updates cannot duplicate a press or leak a release.

This is a manual integration checklist, not a claim that the game, controllers, Configuration Manager, or Jewelcrafting have been exercised in this environment. Automated rule tests cover key-down versus held state, disabled bindings, required modifiers, unrelated held keys, gamepad main-key edges across repeated polls, full release after initialization/rebinding, modifier-held repeated presses, blocked presses not replaying, recognition of the installed ConfigManager for input blocking, the client minimum's new 0–100 range, clamping, and the unchanged independent webhook range of 0–500.
